# Prototype data model and contracts

Implemented migration 0001: users (single role), expiring/revocable hashed auth_sessions, append-only audit_events; PostGIS extension enabled. Audit triggers block row updates/deletes; database owners can still bypass these controls. Production requires distinct migration/runtime roles and external audit retention.

Migration 0002 adds missions (assigned operator, field IDs, boundary, waypoints, simulator mode, synthetic-sensor opt-in, lifecycle timestamps), mission events, timestamped observations with optional normalized sensor features, potential detections with source/version/provenance, append-only analyst assessments, append-only survey attempts and an exclusive vehicle lease. Migration 0003 retains survey snapshots in indexed PostGIS geometry; 0004 preserves vehicle identity and generated spatial target points. Migrations are frozen snapshots, independent of future ORM model changes.

Planned polygons, observation positions, sensor footprints and final coverage geometry are separate PostGIS records in SRID 4326. Geographic buffers/areas use geography units in meters/m². The prototype's experimental profile requires synthetic provenance, quality ≥0.8, relative altitude 1–8 m and speed ≤3 m/s; footprints are 2 m discs, unioned and clipped to the planned polygon. Telemetry without sensor observations contributes no coverage. A completed flight never implies 100% surveyed or cleared ground. UTC receipt timestamps and source/processing versions accompany stored observations/results; clients display local time. Subsequent missions with the same area ID retain separate immutable survey attempts. History supports offset/limit pagination independent of the dashboard's latest-500-mission window.

The prototype has one configured `sitl-01` vehicle. A database lease and mission row locks serialize command ownership; only the assigned operator can validate/start/pause/resume/cancel. A supervisor can reassign draft/ready missions. Field access is assignment-scoped. Field stop requests create events without commanding the autopilot. Backend startup/shutdown interrupts outstanding attempts and stops the isolated runtime instead of resuming flight. Run one API process and one test session at a time. Production background job orchestration, raw sensor acquisition, multi-role administration, multiple aircraft, approval policy and external audit retention remain future work.

Module layout: web/src (shared components, planning/map and operational workspace), backend/app (identity, mission orchestration, runtime client, coverage and reports), backend/migrations (schema snapshots), backend/tests (unit, spatial workflows and opt-in actual SITL), detection/ (independent experimental processor), simulation/ (isolated authenticated runtime/MAVLink service), mobile/ (Flutter Field Personnel source), infrastructure/database, scripts/, docs/ and .github/workflows/.

API contract: run backend and open /docs or /openapi.json. Auth uses JSON username/password, bearer session tokens, a 30 minute absolute lifetime and POST logout revocation. Permissions are loaded from the current user record on every request. Web keeps the token in memory; reload signs out locally. Use Vite's same-origin /api proxy in development; production needs HTTPS and a same-origin reverse proxy. Login throttling, password recovery, MFA, deployment hardening remain pending. Bind development services to localhost only.

Operational routes are under `/api/v1`: missions (list/create/detail), validate/start/pause/resume/cancel, supervisor assign, field stop-request, mission detections/coverage/report, analyst target reviews, area surveys, alerts, simulation status and admin audit. Authenticated WebSocket snapshots use `/api/v1/ws/missions/{id}`; send `{ "token": "<session token>" }` as the first message within five seconds. Sessions, active-account status and assignment are rechecked every snapshot. Tokens are never placed in URLs. Reports are authorized per mission, with JSON for detailed provenance/reviews and CSV summaries. OpenAPI is snapshotted in docs/openapi.json.

System-wide raw runtime status requires `system:read` (Administrator by default); it cannot leak an unassigned vehicle position to Field Personnel. Field users get their assigned mission snapshots instead. Report exports additionally require `reports:read` (Administrator, Operator, Analyst and Supervisor defaults), while field monitoring does not grant export permission. Planning, flight execution, assignment, stop requests and analyst reviews each check their own permission as well as applicable mission scope/state.
## Gazebo world visualization contract

`GET /api/v1/missions/{id}/scene` requires an authenticated identity with access to that mission. An inactive mission or nonmatching vehicle lease returns `live:false, pose:null` without querying the runtime. The runtime returns `source: gazebo-world-pose`, `world: default`, `frame: Gazebo world ENU, meters, quaternion xyzw`, and a fresh `x500_0` pose only. These ephemeral poses are for visualization; persisted MAVLink telemetry, sensor readings, detection provenance and coverage calculations remain separate. No scene command or sensor-image endpoint exists.

## Survey area assignments (migration 0005)

`survey_area_assignments` stores name, description, operator_id, created_by, optional UTC deadline, boundary GeoJSON, generated indexed EPSG:4326 Polygon geometry, revision and creation/update timestamps. `survey_area_events` stores append-only snapshots and actor/timestamps. `missions.assignment_id` is indexed and foreign-keyed; nullable for pre-upgrade history, required in every new MissionPlan API request. Supervisor-only mutation and parent-before-child row locks protect ownership, boundary containment, revisions, and draft reassignment. No completed attempt is rewritten by assignment changes.

Read APIs return area status derived from stored flight/survey facts and geometric progress. Completed progress unions current-profile successful completed survey snapshots and clips to the assignment. Active valid footprints, after subtracting completed coverage, and remaining polygons are separate layers. Only complete geometric coverage yields status COMPLETED; rounding incomplete progress caps at 99.99. Legacy free-text mission area_id remains a grouping label, not the assignment relation. See [survey-area-assignments.md](survey-area-assignments.md) and the regenerated OpenAPI contract.


Migration 0006 adds users.denied_permissions JSON, default empty. Effective permissions are the current role template minus account restrictions. GET /api/v1/admin/roles exposes templates; PUT /api/v1/admin/users/{user_id}/access updates role/active/restrictions and revokes sessions. Identity includes active and denied_permissions.
