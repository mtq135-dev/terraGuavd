## Survey area assignments — 25 October 2026

The user now requires Supervisor-owned large polygons and contained operator sub-missions. New mission requests must include `assignment_id`; the older free-text mission `area_id` remains a survey-history grouping label and cannot substitute for authorization. Migration 0005 leaves earlier missions unassigned to preserve history and their existing workflow; no new unassigned missions can be created.

The coverage requirement is conservatively 100% geometric coverage from current-profile successful completed survey attempts. Failed/cancelled attempts retain their evidence in history but do not count toward completed assignment area. Valid live footprints are shown separately, never counted as completed. An incomplete area cannot round up to 100%. The current profile is explicitly synthetic/experimental, not evidence of landmine clearance.

Supervisors may modify metadata, boundary, or operator using revision checks. Active flights block changes. Updated boundaries must contain all linked mission polygons. Reassignment transfers unflown drafts and forces revalidation; previous survey records are not rewritten. Assignments are capped at 100 km², without relaxing existing per-mission/SITL home constraints. Exact polygon/route containment is a planning rule; this change does not install an aircraft geofence.

## Operator partition-planning review (2026-11-06)

The parent survey area remains Supervisor-owned; the Operator manually creates one contained polygon/route and selects one UAV for each child mission. Previously the plan map hid sibling polygons, started with unrelated default geometry and exposed a legacy grouping label as a second apparent area selector. Planning now starts empty, explains the sequence, displays loaded sibling polygons/routes/UAV labels, resets geometry/UAV after save, provides drawing undo/new-sub-area controls and keeps raw coordinates under advanced editing. New UI requests derive the survey-history grouping label from the selected assignment ID; older stored labels/history remain untouched. Fleet availability refreshes while planning.

Disjoint and overlapping child polygons are supported within one parent; separate assignments may hold independent missions and progress. Completed valid coverage unions only within each assignment, so overlap between different parent assignments is not globally deduplicated. There is no automatic partitioner, automatic coverage-route generator, shared-airspace coordination or conflict avoidance. The entire submitted waypoint line is checked inside the child polygon and the child polygon inside its parent at create/validate/start. This is not an autopilot geofence: takeoff/return-to-launch may leave the child polygon. The isolated runtime also limits uploaded routes to its simulator-home vicinity; a valid large/global assignment does not make arbitrary remote missions executable. No flight code or permissions were changed.

## Geographic simulator-origin correction (2026-11-06)

User observed `Plan is too far from simulator home` after planning a Saudi sector. Cause: the planner allowed geographically valid assigned sectors, but the runtime still started every isolated world at PX4's default Swiss origin. The earlier preview stated only ready-to-save but did not configure a matching execution origin. Installed px4-rc.gzsim lines 98–109 explicitly support PX4_HOME_LAT/LON/ALT by setting Gazebo spherical coordinates before spawning the model.

On explicit authorized mission start, the backend now derives the isolated world origin from that mission's first survey waypoint. Runtime start accepts only finite bounded latitude/longitude, retains the fixed allowlisted model/localhost transport, and sets all three PX4_HOME_* environment values. Reference elevation remains the synthetic flat world's 488 m default, not measured terrain elevation. A running armed world cannot change its model or origin. Startup still does not upload, arm or start; existing readiness/prearm/assignment/lease checks apply.

The existing local route extent guard is retained, and matching first-waypoint extent checks now run during preview and explicit execution. Oversized executable sectors must be split rather than weakening the runtime guard. Geometric draft save/validation retains its existing large-plan behavior; no size cap was reintroduced there. Actual MAVLink position is never relabelled or fabricated. Each independent simulator has its own local world origin; this remains separate-world concurrency, not shared-airspace collision avoidance. Scene poses remain local ENU. No database schema changes or edits to existing attempts were made. A saved sector can be copied to a new draft to retry while preserving the original failed attempt. Runtime HTTP errors now extract the readable detail instead of nesting raw JSON.

Actual origin test passed: a Saudi-origin x500 mission completed with 91 observations; measured first position 22.7713498, 47.1604996 matched configured origin 22.77135, 47.1605. The independent lease was released and the runtime stopped/disarmed. Evidence: relocated-origin-evidence.json. Tests cover armed-origin rejection and environment setup; no prearm checks were relaxed.
